# AuNote 问卷 AI 转换指南

本文件面向 ChatGPT、Claude、Gemini、Codex 等 AI。目标是把 Word、PDF、Markdown 或自然语言问卷可靠转换为 AuNote 可导入的 `schemaVersion: 1` JSON，而不是重新设计格式。

## 0. 最快可靠路径

处理普通问卷时，不要扫描整个仓库，也不要阅读`js/app.js`：

1. 只阅读本指南并转换原问卷；需要不常用字段时再查[`questionnaire-template.md`](questionnaire-template.md)或[完整示例](../examples/full-feature-questionnaire.json)。
2. `questionnaire.schema.json`是机器校验来源，不要求AI逐行解释或把整份Schema载入回答上下文。
3. 若可以运行仓库命令，生成后执行：`node tools/validate-questionnaire.mjs "问卷.json"`。
4. 最终文件必须只有一个JSON对象，不包含Markdown代码围栏、解释文字、注释或尾随逗号，并保存为不带BOM的UTF-8。
5. 验证通过后，仍由用户确认题目顺序、选项、必填状态、单位和分析方法。

导出前硬检查：`schemaVersion`必须是数字`1`，不是字符串`"1"`；`schemaVersion`、`id`、`version`、`title`和`fields`必须直接位于最外层，不能再包在`questionnaire`、`template`或其他属性中。

## 转换前的能力差距检查（强制）

生成JSON前，必须先提取原问卷中的全部要求，不能只提取题目和选项。至少检查：同页显示与分页、视觉分组、矩阵题、条件跳题、题目联动、排序、日期、文件上传、签名、图片交互、数字范围、小数位数、固定步长、重复测量、分析方式、A/B对比展示，以及其他特殊布局或交互。

对每项要求判断为以下状态之一：

- **完全支持**：当前schemaVersion 1和PWA能够按原要求实现；
- **部分支持**：能够保存核心答案，但校验、布局、交互或展示存在差异；
- **不支持**：当前问卷JSON和PWA无法表达或执行；
- **信息不足**：原文不足以确定题型、行为或配置。

只要存在“部分支持”“不支持”或“信息不足”，必须在交付JSON之前：

1. 引用或准确概括原始要求；
2. 说明AuNote缺少或不同的能力；
3. 说明JSON采用的降级处理及其实际差异；
4. 必要时先询问用户是否接受；
5. 不得静默删除要求，不得发明未定义字段；
6. 不得仅因JSON通过Schema校验，就声称原问卷已被完整实现。

推荐回复顺序：**能力差距检查 → 假设或待确认事项 → 可导入JSON/JSON文件 → 必要的使用提醒**。没有发现差距时可以只写一句：“未发现当前AuNote无法映射的要求。”，然后直接交付JSON，避免增加无意义篇幅。能力提醒写在AI回复或单独报告中，不得塞进问卷JSON的未定义字段。

常见判断示例：

| 原始要求 | 支持状态 | JSON中的处理与提醒 |
| --- | --- | --- |
| 两道相邻题在同一页显示 | 完全支持 | 两题设置相同`page`；不得只靠字段相邻冒充同页 |
| 1–5分并允许一位小数 | 部分支持 | 使用`number`和`integer: false`；说明文字保留1–5和一位小数要求，但当前不能强制范围或小数位数 |
| 根据上一题答案跳过后续问题 | 不支持 | 不编造跳题字段；向用户确认是否接受全部题目顺序显示 |
| 矩阵式批量评分 | 不支持 | 可在用户同意后拆成多道独立题；说明交互与原矩阵不同 |

## 1. 最小结构

```json
{
  "schemaVersion": 1,
  "id": "study-id",
  "version": "1.0",
  "title": "问卷名称",
  "description": "问卷背景",
  "recordLabelField": "participantName",
  "fields": []
}
```

- 保持 `schemaVersion: 1`，不要发明新字段来模拟未支持能力。
- `id + version`标识独立版本。同一研究修订问卷时保持`id`并更改`version`；不同研究使用不同`id`。
- `fields`严格保持原问卷顺序。
- 问卷包含姓名、参与者编号或样本编号时，用顶层`recordLabelField`明确引用该题ID，避免样本列表无法识别显示名称。优先使用研究中最稳定且适合辨认单个样本的字段。

## 2. 原始题目映射

| 原始问卷形式 | AuNote `type` |
| --- | --- |
| 姓名、编号、短答 | `shortText` |
| 访谈记录、原因、备注、开放回答 | `longText` |
| 单个可含小数的数值 | `number`，`integer: false`或省略 |
| 单个只能为整数的数值 | `number`，`integer: true` |
| 同一指标重复测量2～10次 | `repeatedNumber` |
| 只能选一项 | `singleChoice` |
| 可以选多项 | `multiChoice` |
| 有限、连续整数档位评分 | `rating` |
| 章节标题、指导语、过渡说明 | `section` |

无法无损映射的交互（矩阵题、排序、日期、文件上传、签名、跳题逻辑等）不得伪装成另一种题型。必须按“转换前的能力差距检查”列出差异，并向用户确认拆题、改写或暂不导入。

## 3. ID 命名

- 推荐小写英文 `lowerCamelCase`，如 `participantAge`、`leftEarThickness`；选项如 `noPreference`。
- ID在当前问卷内必须唯一，语义稳定，不包含姓名或参与者数据。
- 不用题号作为唯一语义，例如优先`wearDuration`而非`q7`。
- 版本更新时，同一含义的题保持原ID；含义实质变化时使用新ID，避免旧答案被误解。

## 4. 问卷文案克制原则：忠实、简洁、无防御性解释

**问卷是给研究人员或受访者直接执行的，不是 AI 的研究方法讲义。** 转换目标是保持题意、口径和操作条件不变，不应为了显示严谨而扩写每一道题。

- `label`：优先保留原句；如用户要求润色，才进行必要的精简和语病修正，不改变题目的时间范围、对象、量表含义和提问方向。
- `description`：**默认为省略**。只有原文明确给出、或者不写就无法正确作答的测量方法、操作步骤、关键定义和必要限制才保留。原文必要说明不可擅删。
- `placeholder`：只写确有帮助的短示例；不要把使用说明、研究解释或免责声明移入占位文字。
- 不添加“请结合实际情况”“请客观、认真作答”“本题旨在了解……”“如有疑问请询问研究人员”等套话，除非它们是原研究不可缺少的指导语。
- 不擅自增加问题、选项、评分解释、解释性 `section` 或访员备注。缺乏信息时在 AI 与用户的**对话中**提出精简问题，不要把猜测写进问卷。
- 设计建议、能力差距、假设与转换提醒属于**交付说明**，不能附加为受访者看到的题目说明；没有风险或差距时不输出冗长自我辩护。

**例 1 — 不加多余说明：** 原题“请评价耳机佩戴舒适度（1–5 分）。” → `label` 维持原题，`description` 省略；不生成“请根据实际体验客观评分”等内容。

**例 2 — 必须保留操作口径：** 原题“在耳轮上端测量最小耳厚，每次保持卡尺垂直，重复 3 次，单位 mm。” → 测量位置、卡尺姿态、次数和单位必须保留，不能为了简短删去。可按题型能力将关键口径放在 `description`。

### required、description 与 placeholder

- 只有原文明确写明“必填”、星号且图例明确表示必填，或用户明确确认时，才设置`required: true`。
- 原问卷没有说明是否必填时，使用`required: false`；不得静默猜测为必填。
- `label`保存真正的问题文字。
- `description`保存作答口径、测量方法、访员提示或必要背景，不把关键条件塞进`placeholder`。
- `placeholder`只提供短输入示例，如“例如：28”或“输入读数”；它会在输入后消失，不能承载必须阅读的规则。
- `shortText`和`longText`均可通过`allowAnonymous`提供匿名记录；只有原问卷或用户明确需要时才开启。手机内通用编辑器当前只为短文字显示该开关。

## 5. 单选、多选与“其他”

- 单选使用`singleChoice`，多选使用`multiChoice`；不要根据选项数量猜题型，应依据“单选/可多选”等原文。
- 每个选项包含稳定、唯一的`id`和原始`label`，不得擅自合并、删改或补充选项。
- “无／以上皆无／不适用”若与其他多选项互斥，在该选项设置`exclusive: true`。
- “其他，请说明”使用选项的`textInput`。只有原文要求选择“其他”后必须说明时，才设置`textInput.required: true`。
- Excel Responses导出选项文字而非选项ID；多选以中文分号连接；补充文字导出为“选项：文字”。

## 6. 数字题

- 明确只能整数时设置`integer: true`；测量值、比例或允许小数的评分使用`integer: false`或省略。
- `unit`只写单位，不写解释，例如`mm`、`岁`。Excel Responses表头会包含单位。
- AuNote schemaVersion 1当前接受非负十进制数；负数、科学计数法、范围上下限校验尚无对应配置。原问卷需要这些能力时必须告知用户限制。
- 如果原问卷要求“1–5分评分，但允许3.2、3.5、4.7等小数”，必须使用支持小数的`number`，不能转换为当前整数型`rating`。除非未来 AuNote 已新增连续评分能力。

## 7. 重复测量

- 只有同一个指标对同一参与者重复测量时使用`repeatedNumber`，不要把多个不同问题合并成重复测量。
- `repeatCount`为输入框总数，必须是2～10的整数。
- `minEntries`来自原文允许的最少有效次数；未说明时不要猜。应询问用户；无法询问时，非必填题使用0，必填题使用1，并明确标注该保守处理。
- 可设置`integer`、`unit`和`placeholder`。填写必须从第1次开始连续，不可跳格。
- Excel Responses会输出每次原值、参与者内平均值和最大差值。

## 8. rating

- `rating`只适用于从整数`min`到整数`max`的连续按钮，例如1～5或0～10；`min`必须小于`max`。
- `labels`按分值字符串配置`short`和`help`，只转录原问卷已有锚点，不自行创造心理含义。
- 原文有“不知道／无法判断／不适用”等独立答案时，可用`unknownOption`；不要把它强行编码成某个数字。
- 小数评分、滑杆或视觉模拟量表不能用`rating`冒充，按数字题规则处理并说明交互差异。

## 9. section

- 用`section`保留章节标题、访员说明和不需要答案的过渡页。
- `label`为章节标题，`description`为说明；不设置`required`，也不会导出Excel Responses列。
- 不要把需要用户确认或作答的内容转换为`section`。

## 10. 图片

当研究目的涉及人体或产品的**位置、接触面、疼痛范围、主观压力感分布或热力图**时，请先阅读[AI 图片标注研究指南](image-annotation-ai-guide.md)，主动询问用户采用已有底图还是由 AI 按[底图生成规范](../prompts/annotation-base-image.md)生成。**在确认视角、研究指标、图片尺寸和实际文件来源之前，不要交付带占位图片路径的“可导入”问卷。**

- 普通导入JSON使用`data:image/...;base64,...`内嵌图片，保证离线可用；禁止HTTP/HTTPS外链。
- `alt`应简洁说明图片传达的内容。图片本身包含关键作答信息时，必须提供足以理解的替代文本。
- `./assets/...`仅供已随AuNote项目发布并由Service Worker缓存的内置资源使用；AI不能假设用户设备已有某个本地文件。
- 普通图片不进入Excel Responses。`imageRange`图片范围标注题支持在图片上涂画区域，点按也可记录很小的范围；仅当研究目标确实涉及空间位置或范围、并能提供稳定的底图资源时使用；AI可主动建议这种题型，但不能为了增加功能而改变原研究意图。须给出`view`、`annotationType`、`brushSize`、1～2个`levels`和底图原始`width`/`height`，每题独占一页。同一研究问题拆为多个图片页时，可为这些题填写相同的`questionNumber`，但答案仍分别保存。详见[格式说明](questionnaire-template.md)及[七页示例](../examples/ear-image-range-test.json)。普通外部AI不可假定用户设备已有`./assets/...`，应内嵌图片或先确认图片会随应用缓存。

## 11. 多题同页

- 默认每道题独占一页。只有原问卷或用户明确要求同页呈现时，才添加`page`。
- 需要同页显示的连续相邻题目使用同一个非空字符串，例如都设置`"page": "participantInfo"`。
- 只有连续相邻且`page`相同的题目会合并显示；不要在不相邻题目上重复同一值，以免让配置难以阅读。
- `page`只改变填写界面分页，不改变字段顺序、答案结构或Excel Responses。不要为了减少页数自行合并不同问题。
- 当前PWA问卷编辑器不编辑`page`；AI转换或人工编辑JSON时才配置。

## 12. analysis / analyses：AI 主动识别并保守配置简易分析

即使用户没有要求“简易分析”，AI 也要主动识别研究中值得观察、且当前 AuNote 支持的指标。**优先使用新版 `analyses` 数组**，使同一问卷可以在研究过程中同时查看不同类别的分析。不得为了制作图表改变原研究问题或捏造分析假设。

| 研究指标 | 自动配置 | 主要规则 |
| --- | --- | --- |
| 耳厚、夹持力、连续数值与重复测量 | `descriptiveDistribution` | 有效样本数、均值、中位数、极值、标准差等；重复测量先按参与者平均 |
| 舒适度、满意度等整数评分 | `categoricalFrequency` | 每档人数与比例，包括“无法判断”等合法独立选项 |
| 单选偏好、多选原因等类别题 | `categoricalFrequency` | 每个选项被多少有效参与者选中；多选比例之和可以超过 100% |
| 接触位置、疼痛范围等 `imageRange` | `imageRangeHeatmap` | 按固定底图、视角、等级做多人叠加人数热力图 |
| 姓名、电话号码、编号、编码值 | 不配置 | 不当作数值研究指标；必要时仍可在 Excel 中查看 |
| 年龄等背景变量 | 视研究目的决定 | 只有与抽样结构或研究目标有关时才加入 |

新配置示例（`fields` 的 ID 必须是真实问卷题目）：

```json
{
  "analyses": [
    {
      "type": "descriptiveDistribution",
      "aggregation": "participantMean",
      "statistics": ["count", "mean", "median", "min", "max", "sd"],
      "fields": [{ "id": "earThickness" }]
    },
    {
      "type": "categoricalFrequency",
      "fields": [{ "id": "comfort" }, { "id": "preference" }]
    },
    {
      "type": "imageRangeHeatmap",
      "fields": [{ "id": "contactSide" }, { "id": "painSide" }]
    }
  ]
}
```

- `analyses` 是非空数组；可以有一个或多个分析配置。**不要同时写 `analysis` 和 `analyses`**。
- 旧问卷的单对象 `analysis` 完全保留兼容，不要求历史问卷迁移。
- `descriptiveDistribution` 只接受 `number`、`repeatedNumber`。默认汇总方式为 `participantMean`；`statistics` 可选取 `count`、`mean`、`median`、`mode`、`min`、`max`、`sd`、`q1`、`q3`。旧 `distribution` 也兼容。
- `categoricalFrequency` 只接受 `rating`、`singleChoice`、`multiChoice`。比例分母为该题**有效作答人数**；同一个人同一选项最多计一次。不要误将所有记录当作都有效。
- `imageRangeHeatmap` 只接受 `imageRange`。按参与者去重，同位置同级多次绘制最多计一人；仅展示层柔化。
- `percentiles`、`binWidth` 等依赖研究设计的配置，只有用户明确要求时才设置；没有依据不主动发明 P20/P50/P80、固定分箱或显著性检验。
- **不是所有题目都要分析**：根据实际研究目标筛选重点指标，避免把分析页面堆满无关图表。
- 交付时可以仅用一句话说明“已自动配置数值统计、选择题比例和区域热力图”，而不是给每道题增加解释。
- 任何尚未支持的研究要求要在 JSON **之外**简短说明；不得假装已有功能或用防御性备注污染问卷内容。

## 13. 禁止猜测与无法映射时的输出

AI不得自行猜测：必填状态、单位、评分上下限、匿名含义、互斥关系、重复次数、最少次数、缺失选项、图片内容、布局、跳题逻辑或特殊统计方法。第12节允许自动添加**已定义的描述性统计、选择题频数和图片热力图**，不等于允许发明研究假设、百分位阈值或用户没提出的检验方法。JSON结构合法不等于原问卷要求已完整实现。

信息不足时按以下顺序处理：

1. 明确列出缺失或冲突的信息；
2. 向用户提出最少量、可回答的确认问题；
3. 在确认前不要输出一个看似可导入但语义可能错误的最终JSON；
4. 若用户要求先给草案，使用保守值（尤其`required: false`），并在JSON之外列出所有假设；不要把备注或TODO写进未定义的JSON字段；
5. 生成后优先运行`node tools/validate-questionnaire.mjs "问卷.json"`（内部使用与AuNote导入相同的校验器）；无法运行命令时再按`questionnaire.schema.json`校验，并逐题核对原文顺序、选项、必填、单位、评分和分析配置。
