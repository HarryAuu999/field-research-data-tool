# AI 协作配置图片标注研究

本指南供 ChatGPT、Claude、Gemini、Codex 等 AI 阅读。适用于用户描述“想用 AuNote 收集某个物体/身体部位的接触、疼痛、压力或摩擦范围”，但尚未准备问卷和标注底图的情况。

**目标：把研究目的变成可在 AuNote 离线采集、可重建坐标和可做人数热力图的问卷。** 不要求研究人员先掌握 JSON 或手动写格式。

- [通用问卷 AI 转换指南](questionnaire-ai-guide.md)：所有题型、能力差距、合法 JSON 与校验。
- [图片底图生成规范及可复用 Prompt](../prompts/annotation-base-image.md)：当用户没有底图时使用。
- [已有耳朵研究示例](../examples/ear-image-range-test.json)：实用 `imageRange` 配置，三张图、接触与两级疼痛。
- [导出数据与热力图分析](image-range-heatmap-analysis.md)：研究完成后的处理方式。

## 何时主动提出使用图片标注？

用户提到“在哪里”“哪个位置”“多大一块”“画出接触区域”“统计最常见疼痛部位”“生成热力图”等空间信息时，主动评估 `imageRange`。**不要在用户不知道这类题型时，只生成一句文字问题或强迫用户用部位选项代替。**

向用户简要说明：可以直接在自定义图片上点一下或自由涂画范围；“点”在此题型中是一小块画笔区域，与涂画共享同一套可叠加数据。接触与疼痛等不同研究指标应分别记录，疼痛程度可用最多两级（当前限制）。

## 与用户沟通的最短决策流程

1. **确认测什么**：接触/疼痛/主观压力感等，是否分为不同问题、是否需要等级。不要把客观物理压力数值和用户主观标注混为一谈。
2. **确认标哪里**：研究对象、左/右、正面/背面/侧面、是否有被遮挡的部位。需要多张图时一图一题，并解释它们属于同一研究问题。
3. **主动询问底图来源（必做）**：
   > “你已经有适合标注的图片吗？可以提供给我；或者由 AI 生成一张简洁、灰度、适合热力图叠加的底图。你倾向哪种？”
4. **决定是否生成**：有图就先检查朝向、可标注面积、清晰度和图像使用权限；无图且用户选择生成，先根据 [底图规范](../prompts/annotation-base-image.md)制作并让用户确认，必要时修正。无法生成图像的 AI 应把提示词交给用户或可用的图片工具，不得假装已经生成。
5. **主动识别分析机会**：即使用户未提到“简易分析”，若研究目的需要汇总多人在同一底图上的标注，应默认建议并配置人数热力图；等级标签仍须与研究人员确认。若同份问卷还存在数值分析需求，应先说明当前只能配置一种内置分析类型并询问优先级。实时热力图展示已采样本的描述性结果，不是因果结论。
6. **生成与交付问卷**：阅读 [问卷转换指南](questionnaire-ai-guide.md)，检查能力边界；制作符合 `schemaVersion: 1` 的 JSON，验证、交付、说明导入与后续数据导出。

用户已有明确要求时不要反复盘问；只问缺少且会改变结果的关键问题。

## 当前 AuNote 已经支持什么？

- `imageRange` 用 `image.src` 加载静态底图，记录归一化笔画点和随笔画保存的 `brushSize`；支持反复补画、撤销。
- `view` 标识观察视角，`annotationType` 标识接触/疼痛等主题，`levels` 允许 **1–2 级**。每张底图独占一页。
- `analysis.type: "imageRangeHeatmap"` 可以在研究中按题、按等级查看多人叠加人数热力图；不同图片、朝向不自动融合。
- 当前同一份问卷 `analysis` **一次只能是一种分析类型**，不应同时声称数字分布与图片热力图可一起配置。
- 原始结果随问卷保存，导出为 XLSX `Responses` 与 `Annotations`；可用 [离线 Python 工具](image-range-heatmap-analysis.md)进一步制图。

**图片不是只放文件名就能导入：** 普通自定义问卷中的外部底图，应以内嵌 `data:image/...;base64,...` 放进 JSON；随 AuNote 应用正式发布、已被离线缓存的内置图片才可引用 `./assets/...`。不要写手机本地路径，也不要写在线 URL 或猜测某资源已经部署。使用图片编码时应保留正确的原始 `width`/`height`，让坐标可恢复。

AI 如果不能读取用户提供的图片二进制内容，就应明确说明缺少图片文件，不能用占位符冒充可导入问卷。经过问卷能力校验并由用户确认方向后才交付最终 JSON。

## 统一坐标及底图管理

- 同一题、同一视角的所有参与者必须使用**完全相同**的图片字节、方向和图像尺寸。
- 研究开始后不要随意替换、重新裁切、镜像或改变底图坐标系。即使视觉相似，旧坐标也不一定能对齐。
- 如果研究确实需要不同人群、左右身体或不同产品，应定义独立题目/视角，避免直接混算。
- 允许用 AI 生成示意底图，但在涉及精确人体尺寸、真实 3D 对应或局部接触曲率时，优先使用可靠的实测照片、扫描或同一 3D 模型的定向渲染。
- 如果图片包含可识别个人信息，确认有权使用且符合研究隐私要求；不要把参与者个人图片提交到公开仓库。

## 项目自带的耳朵范例（沿用现有素材）

[现成 JSON](../examples/ear-image-range-test.json) 是最佳参考，不必另造一套腰部模板：

- 研究对象：耳挂式耳机。
- 接触范围：左耳侧面、侧面截面、耳背面三张图，分为三个页面，单等级。
- 疼痛范围：同样三张图，每张两个等级（一般疼痛、较为疼痛）。
- 图片：`assets/ear-side.png`、`assets/ear-side-section.png`、`assets/ear-back.png`。
- 热力图：各页面各等级按实际标注人数叠加，同一人同一区域重复涂画最多贡献一次。

若某用户研究的是腰痛、座椅支撑或其他形态，AI 应依照相同的**研究决策流程**设计所需图片，而不是直接套用耳朵图的题目数量、疼痛等级或视角。

## 新对话验收脚本

在一个没有既往上下文的新 AI 对话中发送：

> 我准备研究耳挂式耳机佩戴时的接触位置和疼痛范围，想用 AuNote 收集并输出热力图。我还没有图片。项目地址是 https://github.com/HarryAuu999/field-research-data-tool 。请阅读 docs/image-annotation-ai-guide.md、prompts/annotation-base-image.md 和问卷 AI 转换指南，先和我确认需要的底图与研究设计，不要直接编造 JSON。

合格的 AI 应：**主动提供“用户给图 / AI 生成”两个选项**；主动确认视角；区分接触与疼痛；说明最多两级、图片稳定性及真实热力图支持情况；让用户先确认生成图片，再编码进 JSON。

生成图片是否合格，请对照 [底图 Prompt 中的验收标准](../prompts/annotation-base-image.md)。验收的是**能否完成研究配置工作流**，不是仅看图画得是否美观。
